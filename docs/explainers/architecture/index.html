One tool call, step by step

Example: the agent registers a new patient. A filled node shows a built step.

Request path
  1. The agent sends save_patient to apps/web with a shared-secret header.Not built
  2. apps/web checks the secret. Then it asks the EHR for a token.Not built
  3. The EHR checks the client ID and secret. It returns a token that expires in 1 hour.
  4. apps/web sends POST /fhir/Patient with the token.
  5. The EHR validates the FHIR Patient. It writes one NOM row in patient.
  6. The EHR writes one audit_event row. It returns the FHIR Patient.
Rules the EHR applies
  1. No token, no data. Every /fhir/* call without a valid token gets 401.
  2. No duplicate patients. If the phone number exists, the EHR returns that patient (200).
  3. Same phone, any format. The EHR keeps the last 10 digits.
  4. No invented CURP. The CURP is optional. The EHR never generates it.
  5. Errors are FHIR too. Each error is an OperationOutcome.

Mexican rules inside, FHIR outside

The database follows Mexican health-record law. The API follows the international standard. One mapping file connects them: src/fhir/patient.ts.

Inside: NOM-024 and NOM-004
  • Two surnames: primer_apellido, segundo_apellidoNOM-024 Table 1
  • Sex as RENAPO H or MNOM-024 Table 1
  • CURP as the unique key, never generatedNOM-024 6.5.2
  • Clinic CLUES and doctor cédula profesionalNOM-024 catalogs, NOM-004 5.10
  • Audit log: the database rejects UPDATE and DELETENOM-024 3.42 and 6.6.1
  • Intake stays pending_validation until the doctor signsNOM-004 4.4 and 5.10
Outside: FHIR R4
  • name.family plus fathers-family and mothers-family extensionsHL7 core extensions
  • gender male or female, raw H or M in an extensionFHIR Patient
  • identifier with system urn:mx:renapo:curpLocal URN: Mexico has no official FHIR guide
  • Folio EXP-… as the record identifierurn:pokta-clinic:expediente-demo:folio
  • /fhir/metadata CapabilityStatementIntegrators discover what the EHR supports
  • QuestionnaireResponse with a Device author (next)The agent is not health personnel

What the smoke test proves

The test runs against the local EHR and the Docker database. All six checks pass.
