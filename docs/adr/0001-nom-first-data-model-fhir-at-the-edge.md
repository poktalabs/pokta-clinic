# NOM-first data model, FHIR at the edge, agent output pending validation

The mock EHR's tables follow NOM-004 (expediente clínico) and NOM-024 (SIRES identification fields, catalogs, audit log), and FHIR R4 is only the exchange format pokta-clinic speaks; no official Mexican FHIR implementation guide exists, so we use core R4 resources with local identifier systems and the fathers-family / mothers-family name extensions. Because an AI agent is not health personnel and cannot sign a note (NOM-004 4.4, 5.10), the agent's QuestionnaireResponse is stored as a patient-reported complementary document pending the Practitioner's Validation, with the agent recorded as a `Device` author, rather than being written as the Historia clinica. We chose this over a FHIR-first schema (simpler, but foreign to Mexican practice and to the norms an EHR vendor is certified against) and over writing the agent's output straight into the record (faster demo, but legally wrong). Details and section citations: `apps/mock-ehr/docs/data-model.md`.
